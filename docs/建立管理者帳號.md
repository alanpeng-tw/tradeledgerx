# 建立管理者帳號 (Admin Account)

文件中的預設管理者帳號為 **alanpeng / 123456**。後端已支援登入 API，你可用以下任一方式建立這位管理者。

---

## 方式一：執行腳本（推薦）

- **有 Poetry**：在 **backend** 目錄下執行（需先 `poetry install`）  
  `poetry run python scripts/create_admin.py`
- **沒有 Poetry**：可先安裝 [Poetry](https://python-poetry.org/docs/#installation)，或改用下方**方式二**，只裝 `passlib` 產生雜湊後在 MongoDB 手動新增一筆使用者。

執行成功後會出現「已建立管理者帳號: alanpeng / 123456」，即可用此帳密登入前端。

---

## 方式二：在 MongoDB 手動新增一筆使用者

1. **在 MongoDB 建立 `users` 集合**  
   若 `tradeledgerx` 資料庫裡還沒有 `users`，可先隨便新增一筆再刪除，或等第一次用程式寫入時自動建立。

2. **取得密碼的雜湊值**  
   - **有 Poetry**：在 **backend** 目錄下執行  
     `poetry run python -c "from app.routers.auth import hash_password; print(hash_password('123456'))"`  
   - **沒有 Poetry**：用虛擬環境安裝 passlib 後產生雜湊（密碼可改成你要的，例如 `hero111`）：  
     ```bash
     cd backend
     python3 -m venv .venv
     source .venv/bin/activate          # Windows: .venv\Scripts\activate
     pip install "passlib[bcrypt]"
     python -c "from passlib.context import CryptContext; print(CryptContext(schemes=['bcrypt']).hash('123456'))"
     ```

   終端機會印出一串像 `$2b$12$...` 的字串，複製起來。

3. **在 MongoDB Compass 新增一筆文件**  
   - 連到 `tradeledgerx` 資料庫  
   - 選（或建立）`users` 集合  
   - 點 **ADD DATA** → **Insert Document**  
   - 貼上以下內容（把 `你的雜湊值` 換成上一步印出的字串）：

   ```json
   {
     "username": "alanpeng",
     "hashed_password": "你的雜湊值",
     "role": "admin"
   }
   ```

   - 儲存後即完成。

4. **登入**  
   前端用 **alanpeng** / **123456** 登入即可。

---

## 說明

- **`accounts` 集合**：存的是「交易帳戶」（例如 FTMO、BingX），每個檔案有 `user_id` 對應登入者。
- **`users` 集合**：存的是「登入帳號」（使用者名稱、密碼雜湊、角色），管理者就是在此建立。
- 建立好管理者並登入後，再在畫面上或透過 API 建立/管理「交易帳戶」即可。
- **密碼對應**：若你在 MongoDB 裡手動建的雜湊是用某個密碼產生的（例如 `hero111`），登入時就要用**那個密碼**（alanpeng / hero111）；若用 `create_admin.py` 建立則是 alanpeng / 123456。

## 登入失敗怎麼檢測

### 1. 用 curl 測試登入 API

後端有跑起來時（例如 `docker-compose up` 或 `uvicorn app.main:app --port 8000`），在終端執行：

```bash
curl -X POST http://localhost:8000/api/v1/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alanpeng","password":"123456"}'
```

- 若回傳 `{"detail":"Invalid username or password"}`：代表後端有收到請求，但使用者不存在或密碼錯誤。
- 若回傳 `{"access_token":"...","token_type":"bearer"}`：代表登入成功。
- 若連線失敗（Connection refused）：代表後端沒跑或網址/port 不對（本機開發預設 8000，Docker 為 8081→8080）。

### 2. 執行檢測腳本（檢查 MongoDB 與密碼驗證）

在 **backend** 目錄執行（需能連到 MongoDB，且已 `poetry install` 或虛擬環境有裝好依賴）：

```bash
cd backend
poetry run python scripts/check_login.py
```

或虛擬環境：

```bash
source .venv/bin/activate
pip install motor pydantic-settings passlib[bcrypt]  # 若尚未安裝
python scripts/check_login.py
```

腳本會檢查：

- 是否找得到 `username = alanpeng` 的使用者
- 文件中是否有 `hashed_password` 欄位（注意是底線，不是 `hashedPassword`）
- 密碼與該雜湊是否相符（腳本預設驗證 **123456**；若你的 DB 是手動建且密碼為 hero111，請將 `scripts/check_login.py` 裡的 `password = "123456"` 改為 `"hero111"` 再執行）

依腳本輸出的 ✓ / ❌ 判斷問題在哪一關。

### 3. 從後端 log 分辨「找不到使用者」還是「密碼錯誤」

登入失敗時後端會打一筆 log，**reason** 會標明原因（不記錄密碼）：

- `login_failed username=alanpeng reason=user_not_found` → 資料庫沒有這個 username。
- `login_failed username=alanpeng reason=password_mismatch` → 有這個使用者，但密碼不對。

**Console**：若後端用 `docker-compose` 跑，在 `docker compose logs -f app` 裡可以看到上述 log。

**Log 檔**：若要寫入檔案，設環境變數 `LOG_FILE`。Docker 已在 `docker-compose.yml` 設 `LOG_FILE=/tmp/app.log`，重啟容器後可用 `docker compose exec app cat /tmp/app.log` 查看；或改為掛載到本機目錄（例如 `./logs:/var/log/app`、`LOG_FILE=/var/log/app/app.log`）方便查看。

### 4. 常見問題

| 狀況 | 可能原因 |
|------|----------|
| 找不到使用者 | 集合名稱不是 `users`、資料庫不是 `tradeledgerx`、或 username 打錯（需完全一致，例如 `alanpeng`） |
| 沒有 hashed_password | 欄位名要叫 `hashed_password`（底線），不能是 `password` 或 `hashedPassword` |
| 密碼不符 | 雜湊不是用「你現在輸入的密碼」產生的，或複製雜湊時被截斷、多了空格 |
| 前端打不開 / 登入沒反應 / 無法連線後端 | 確認前端 `VITE_API_URL` 與後端一致：**後端用 Docker** 設 `VITE_API_URL=http://localhost:8081/api/v1`（在 frontend 目錄建 `.env` 或改 `.env.example` 後複製為 `.env`）；**本機 uvicorn** 則用 `http://localhost:8000/api/v1`。改完需重啟前端（`npm run dev`）。 |
